# C06 · Supplier data requests (claim)

Spec: `docs/pcf/pages/C06-supplier-requests/CLAUDE.md` (ESG-lite_FE) and the
phase 3 row of `docs/pcf/foundation/E2-ai-assist/CLAUDE.md`.

Plan (PRs into `redesign/integration`):

1. `[C06 1/5]` python_AI_service `POST /v1/pcf/parse-declaration`: a supplier
   EPD/PCF PDF or a PACT JSON → declared unit, kgCO2e per declared unit,
   boundary, standard, reference period, validity, verifier, GWP set. Every
   field carries `confidence` and `reason`; a PACT file is read without the
   AI, a PDF goes through OCR and the AI. A boundary other than the one the
   caller expects is flagged (`boundary_mismatch`), never silently accepted.
   Raw file kept as evidence (`pcf_evidence`, kind `declaration`).
2. `[C06 2/5]` ESG-lite: `SupplierRequest` entity + `migrate:supplier-requests`,
   manager endpoints under `/pcf/supplier-requests` (list, create, resend,
   detail, delete), tokenised link, dev mail sink (no real email).
3. `[C06 3/5]` ESG-lite: public `/public/supplier-requests/:token` (open,
   submit value or file), accept → company MaterialFactor (licence
   `supplier`) linked to the input, reject, owner notification.
4. `[C06 4/5]` ESG-lite_FE: `/products/suppliers` table, "Ask supplier"
   modal with the exact message and an explicit Send, review drawer with
   AI chips, accept with boundary check.
5. `[C06 5/5]` ESG-lite_FE: public supplier upload page `/supplier/:token`
   and the "Ask supplier" entry points from C03 hotspots and C02 lines.

Rules: dev mail sink only, no real email until the product owner says so.
