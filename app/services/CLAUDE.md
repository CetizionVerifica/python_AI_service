# IM11 · Bulk upload (P27) on the plans API (python_AI_service + ESG-lite_FE)

> Blueprint spec (ESG-lite `docs/mcp-import/later/IM11-bulk-upload-on-plans/CLAUDE.md`). This copy covers the AI service's part; the page's part is in `ESG-lite_FE/src/features/bulk-upload/CLAUDE.md`.

## Outcome
The in-app Bulk upload page uses the same plans and calculation as Claude. The Python import calculation is retired, so there is one engine.

## Build
- AI service keeps: upload, header detection, column mapping, unique categories. Its `/v1/excel/preview` and `/v1/excel/import` turn mapped sheet rows into `ImportRow`s and call ESG-lite `POST /imports/plans` (+ append, commit) with the caller's token (forwarded Bearer), `channel: "bulk_upload"`. `excel_parser` calculation code paths stay until the switch PR, then are removed in the same PR (definition of done 6).
- FE Preview step shows the plan's issues and totals (same components as the IM10 batch view where shared, via src/ui); Import step commits the plan.
- Snapshot: the current `ci/tests` import snapshots must give the same totals through the plan path (or the PR lists every moved figure and why).

## Own tests

## As built (AI service, 2026-10-12)

Files: `app/services/excel_plan_client.py` (new), `app/api/excel.py` (`/preview` and `/import` rewritten), `app/services/excel_parser.py` (calculation and insert path removed, `load_mapped_sheet` added), one setting (`ESG_LITE_API_URL`, `app/core/config.py`) and one lookup (`company_id_for_site`, `app/core/database.py`). Tests: `ci/tests/test_excel_plan_client.py`.

- **What this service still does.** Stores the file (`/upload`), detects the header row, maps columns (`map_df`), lists the sheet's categories (`/unique-categories`), claims a document so one file imports once, and deletes the file after the commit. It no longer resolves names, picks factors, converts units, computes totals, builds FERA twins, checks duplicates or mode locks, or inserts emission rows. Those are ESG-lite's emission write service (IM1) behind the plans API (IM2).
- **`ESG_LITE_API_URL`** (default `http://localhost:3000`) is where the plans API lives. Requests carry the caller's own `Authorization: Bearer` token, taken from the incoming request and never the service key, so ESG-lite applies the caller's scope (sites, categories, client) exactly as it would to the browser. A Superadmin's plan names the client with `company_id`, looked up from the site; other roles send none (their own client).
- **Sheet row → `ImportRow`** (`import_row_from_record`): `emission_category` → `activity_name`; `activity_value` → `activity_value` (a number; `"1,200"` counts); `activity_data_unit` → `activity_unit`; a mapped `date_of_reporting` cell → `period: { kind: "monthly", date }` (day-first, as always), else the upload's month-end date; a yearly upload (`reporting_period: "yearly"`, `year_type` CY/FY, `year`; ESG-lite F-21) → `period: { kind: "yearly", year_type, year }` on every row, date cells not read; every other mapped key is a form field under `fields` as the sheet's text (ESG-lite parses numbers itself, as it does for a typed form), `extra_<key>` under `key`. `row_ref` is `Row N`, N = 1 for the first data row under the header, the number the skipped-rows file always used. Rows the plans API would refuse as a whole request (no category, no unit, a non-numeric value, no value and no fields) are not sent: they are listed as local issues (`MISSING_CATEGORY`, `MISSING_UNIT`, `VALUE_NOT_NUMERIC`, `MISSING_VALUE`, and `TEXT_TOO_LONG` for a category, unit or field value over 300 UTF-16 units or a field name over 100, ESG-lite's `IMPORT_LIMITS`) on the preview and counted as skipped on the import. A zero value is sent and comes back `NON_POSITIVE_VALUE`.
- **Chunking.** `POST /imports/plans` with the first 2,000 rows, then `POST /imports/plans/:id/rows` per 2,000, each with the version the previous answer returned. A sheet with more than 20,000 rows to import is refused here (422) before any call. The unticked categories are left out before counting (`not_selected`).
- **`/v1/excel/preview`** plans the sheet (`plan_sheet`) and answers `{ plan, rows, total_rows, page, page_size, not_selected, sheet_rows }`: `plan` is the IM0 `ImportPlan` without rows (`plan_id`, `version`, `status`, `counts`, `totals`, `issues_summary`, `expires_at`), local issues added to its counts and summary (`local: true`); each row is the PlannedRow flattened to what the Preview table reads (`row`, `row_ref`, `state`, `issues`, `emission_category`, `activity_value`, `activity_data_unit`, `global_category_name`, `factor_value`, `factor_year`, `denominator_unit`, `total_emission`, `fera_total_emission`, `date_of_reporting`, `row_error` = the error messages, `row_warning` = the warnings, plus the form fields). With `plan_id` the call only pages that plan (`page`, `page_size` ≤ 200, `state`), making no new one. `cancel_plan_id` cancels the plan of an earlier preview of the same upload first, so re-mapping doesn't pile up drafts (ESG-lite allows ten per user).
- **`/v1/excel/import`** commits the previewed plan (`plan_id` + `version`) with `skip_rows_with_issues: true` and the idempotency key `bulk-upload:doc-<document_id>:plan-<plan_id>`, so a retried call returns the stored batch. Without `plan_id` it plans and commits in one go. The answer keeps the old shape: `inserted`, `fera_inserted`, `skipped`, `skipped_rows` (`row`, `emission_category`, `reason`; plan issue rows from `GET …?state=issue` plus the local ones, capped at 1,000), `not_selected`, `total_rows`, `upload_batch_id` (null when nothing was inserted), plus `plan_id` and `plan`. The document is claimed before the commit and released if ESG-lite refuses, so the file can be imported again; after a commit it is marked imported and deleted as before.
- **Errors.** ESG-lite's own status and IM0 body (`{ code, message, details }`) travel on unchanged under `detail`, so a `409 IMPORT_PLAN_VERSION_CONFLICT` (rows changed on re-check) or `422 IMPORT_PLAN_HAS_ISSUES` reaches the page as such; an unreachable ESG-lite is `502 ESG_LITE_UNREACHABLE`. Nothing from a sheet is logged: log lines carry ids and codes.
- **Behaviour that changed with the engine.** A value column is now required unless the form has a calc spec (the old path guessed a value from any numeric column); extra fields are stored in `activity_data` with the form's fields (the old path put them in `extra_data`); a row with a zero total is an issue, never saved; duplicates, mode locks, FERA twins, factor-year fallback and audit rows follow the typed-entry rules exactly, because they are the same code. Totals: the three sheets of the retired `bulk_import` snapshot were run through the plan path against a local ESG-lite on the same reference data. Every source row keeps its `total_emission` except one rounding: the per-method product row `765.4` (Python's `round` on the product) is `765.41` (the engine rounds the way a typed entry does). FERA twins match except the row dated in FY 2026 (`2200 litre` Diesel, `2026-10-01`): the old path fell back to the nearest FERA factor year and wrote a `1342.0` twin; the engine wants an exact FERA factor year (`findExactForYear`), as it does for a typed entry, so no twin is written. Both are listed in the PR.
- **Removed** (`excel_parser.py`): `get_preview_rows`, `import_all_rows`, the factor index, category resolver, calc-spec product, value heuristic, FX refresh and the FERA logic; `UNIT_CONVERSIONS` stays (physical units only, no currency) because the PCF unit reader (`pcf_units`, E2) reads it; tests `test_import_snapshot.py`, `test_import_guards.py` and the snapshots they locked (`bulk_import`, `spec_activity_values`, `activity_value_heuristic`, `unit_conversions`, `emission_rounding`). `test_calculation_snapshot.py` keeps the parsing helpers the sheet reader still uses. The emission insert helpers in `app/core/database.py` are now unused and left for a follow-up (shared file).

## Smart Excel import contracts (XI0, 2026-10-14)
Plan: ESG-lite `docs/excel-import/` (00-plan, 01-contracts, modules/XI0–XI6; tracking issue python_AI_service #30). Approved by Shyam 2026-10-14; imports are **site-wise only**: the caller names one site, every sheet maps into that site's categories, rows naming another site get `SITE_NOT_ALLOWED`.
- `app/schemas/mapping.py` is the pydantic twin of ESG-lite `src/imports/mapping.ts`: `MappingProposal` (document_id, site_id, sheets; every sheet must carry the proposal's site_id), `SheetProposal`, `ResolvedCategory` (fixed | column), `SheetPeriod` (column | monthly_fixed | yearly | months_as_columns), `FieldMapping`, `ProposedActivityMatch`, `SiteColumn`, `MappingProfile`, `ImportRowMeta`, the `MAPPING_*` limits and the row issue codes this service may raise locally. Unknown keys are ignored, as ESG-lite strips them. The "every name must exist in the caller's context" rule is XI2 code, not the models.
- Fixtures `ci/fixtures/xi0/*.json` are identical to ESG-lite's; `ci/tests/test_mapping_contracts.py` parses every one of them. Change a fixture in both repos in the same wave.
- XI1 (workbook reader), XI2 (mapping engine, `POST /v1/excel/propose`) and XI6 (evals) build on these models; nothing else changes behaviour in this PR.
